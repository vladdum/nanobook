## What we shipped

- `sw/replay/` — independent ITCH 5.0 parser, slicer, MoldUDP framer, 32-byte
  BookEvent serializer, event-stream diff tool (5 modules + 5 pytest suites,
  ≥ 24 cases total).

  idempotency + cosim-slice + 10 M-msg cosim per pcap + m03 carry-over.

## What took longer than planned

- __NASDAQ pcap availability.__ The original M04 spec pinned 2024 days
  (10-16 normal, 09-18 FOMC, 08-05 yen-unwind quake). All three return HTTP
  404 on `emi.nasdaq.com` today; the legacy `ftp.nasdaqtrader.com` server is
  offline; the trader-page route is gone. Re-pinned to 2019 days the free
  mirror still hosts: 03-27 normal, 10-30 real FOMC announcement, 08-30
  month-end of the Aug 2019 Yuan-devaluation week. Required spec amendment
  before Phase A could proceed.
- __`fetch.sh` URL bug + dead FTP path.__ The historical fetch script used
  `Nasdaq_ITCH` (underscore) but the live mirror path is `Nasdaq ITCH` (space,
  URL-encoded as `%20`). Silent 404 every time. Fixed alongside the date
  re-pin; also dropped the dead ftp:// fallback to avoid 30 s connect-timeouts
  per file.
- __Hibernate-mid-fetch.__ The 13 GB initial download was interrupted by host
  hibernate. The original `fetch.sh` had a `[[ -f file.gz ]] then skip` check
  that would have _falsely_ "skipped" a half-downloaded file as "have it" on
  re-run. Replaced with `curl -C -` (auto-resume) + `--retry 3` so partial
  downloads continue byte-accurately across hibernate / network drops. The
  resume picked up at byte 4,916,699,753 — exact pre-hibernate offset — and
  the final SHA matched the locked value.
- __Plan-text completeness gaps.__ Phases B/D/F/G/H all referenced
  `from sw.refbook.include.refbook.book_event import BookEvent, EventType`,
  `EventType.Add` / `.Cancel` / etc., and a `_pad=0` BookEvent field — none of
  which exist in the codebase. The actual API is `BookEvent` from
  `sw.refbook.synthetic_gen` plus flat `EV_ADD/EV_CANCEL/EV_DELETE/EV_EXEC/`
  `EV_EXECPX` constants. `_pad` is baked into the struct format
  `<BBHII4xQQ`, not an attribute. Adapted code to plan (smallest deviation
  from intent); no production-code freeze invariants touched. M02-frozen
  schema preserved.
- __mypy strict + namespace packages.__ `sw/` is an implicit-namespace package
  (no `__init__.py` at `sw/` or `sw/refbook/`), which under `mypy --strict`
  resolves modules under both their full path (`sw.replay.itch_parser`) and
  unprefixed form (`replay.itch_parser`) and reports a duplicate. Added a
  root `mypy.ini` with `namespace_packages = True` +
  `explicit_package_bases = True` so the plan's `mypy --strict sw/replay/`
  invocation works without extra flags.
- __CI required-checks vs path filters.__ Branch-protection (set up post-#28)
  required `verilator-lint`, `verilator-tb`, `python-lint`,
  `itch-decoder-codegen`, `itch-decoder` on every PR. The existing workflows
  were path-filtered to `hw/dv/sw/`, so doc/data-only PRs (e.g. #31)
  triggered no workflow → required checks never reported → mergeStateStatus
  BLOCKED forever. Fixed in PR #32 by removing all `paths:` filters; trade-off
  is ~10–20 min CI per doc/data PR.

## Which risks fired

Cross-reference `docs/superpowers/specs/2026-04-27-nanobook-m04-real-pcap-validation-design.md` §8.

- __"NASDAQ FTP/HTTPS mirror has rotated or removed pinned files between
  download attempts"__ — fired in the strongest possible form: NASDAQ has
  stopped publishing 2021+ files on the free mirror entirely. Mitigation
  (Phase A locks SHAs immediately on first successful fetch) does not help
  when first-fetch is impossible. Spec amended to 2019 days.
- __"Author with same brain may unconsciously share bugs"__ — _did not fire
  on the CI 100 K-msg slices_ because all 100 K messages classify as slow-path
  (R/H/S, see Surprises). Both `_decode_itch` and `itch_parser.parse_one`
  return None for those, so they trivially agree without exercising the
  per-type field offsets. The 10 M-msg developer-host run is the first place
  the fast-path code paths are actually compared end-to-end; that's where this
  risk would actually fire.

## Surprises

- __100 K-msg slices land entirely in the pre-market directory dump.__
  CI's `cosim-slice` job ran clean on first green attempt with the result
  `MATCH: 0 events identical, slow-path counters agree.` for all 3 slices.
  The first 100 K messages of any NASDAQ trading day are exclusively `R`
  (Stock Directory, ~10 K symbols), `H` (Stock Trading Action), and `S`
  (System Event) — all slow-path types in this decoder. Real fast-path
  `A`/`E`/`X`/`D`/`U` activity only starts after the directory enumeration
  and the 9:30 ET market open. The CI gate therefore validates "decoder
  correctly classifies 100 K slow-path messages → 0 events emitted, counter
  bumped 100 000 times" but does NOT exercise the per-type field-extract
  paths. Real fast-path coverage requires either a deeper-into-day slice
  (e.g. start at message offset ~500 000) or the full 10 M-msg developer-host
  sweep in `m04_exit.sh`. Carry to M05: revisit slice generation policy.
- __cocotb 2.0 phase strictness.__ The original `drive_beats` helper used
  `await ReadOnly()` inside the backpressure-poll loop. cocotb 2.0 enforces
  that signal writes only happen in writable phases — the next loop iteration
  attempted to set `dut.s_tdata.value` while still in ReadOnly and raised
  `RuntimeError`. Fixed by matching the existing `drive_payload` pattern:
  sample `s_tready` directly after `RisingEdge` without `ReadOnly`.
- __First M04 PR's branch-protection chicken-and-egg.__ Required-status-checks
  (`verilator-lint` etc.) all path-filtered to `hw/dv/sw/`; the data-only PR #31
  triggered no workflow → checks never reported → BLOCKED forever. Required
  PR #32 to drop `paths:` filters globally before any of the M04 PRs could
  merge. Not strictly an M04 surprise but surfaced during M04 work.
- __cocotb 2.0 deprecation: `task.kill()` → `task.cancel()`.__ Cosmetic
  warning only; updated both cosim TBs.
- __`MODULE` → `COCOTB_TEST_MODULES`.__ cocotb 2.0 prefers the new name; the
  old `MODULE` still works with a deprecation warning. Existing M03 TB
  Makefiles also use `MODULE`; left as-is for consistency, will revisit when
  M03 TBs migrate.

## Carried to M05

- `lob_core` (single-symbol URAM) — entry criterion is M04 bit-exact (i.e., the
  10 M-msg cosim must run cleanly on the developer host; CI 100 K-msg job is
  necessary but not sufficient).
- Width-conversion + 1-event-per-cycle output (M03 carry-over).
- `msg_boundary` byte-pump architecture caps at ~0.11 events/cycle; ≥ 1
  event/cycle requires either a wider `field_extract` path or a re-architected
  boundary stage.
- Self-hosted CI runner with Vivado for per-PR timing gates (M07).
- `EV_EXECPX` generator coverage gap inherited from M02 — still not addressed.
- Multi-message-per-packet replay variant for stress-testing `msg_boundary` on
  real-world message-size mixes.
