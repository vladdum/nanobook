## What took longer than planned

- **Vivado timing iterations.** The plan assumed a single OOC pass; in practice it took three
  rounds. Round 1 failed because `default_nettype none` in `type_dispatch.sv` made Vivado reject
  `input logic *_tready` ports. Round 2 PASSED timing but produced five critical warnings of the
  shape "overwriting previous definition of module" — root cause was per-module `` `include ``
  directives in `itch_decoder.sv` and `field_extract.sv` colliding with `synth.tcl`'s glob-based
  file list. Round 3 (after stripping the includes) was clean. Each iteration is ~30 s of synth,
  but the diagnosis cost dominated.
- **`check_timing.py` regex.** Initial regex matched the Xilinx 2024-era `Worst Negative Slack
  (WNS):` line; 2025.2 timing reports use the `Setup : ... Worst Slack` form, so the script
  silently failed even when synth itself passed. Caught only because the exit-gate flow runs the
  script after every synth.
- **MoldUDP byte-alignment & sticky-valid bugs in `mold_strip` and `msg_boundary`.** Both stages
  passed unit TBs but failed the 10K-event e2e once integrated. Implementer agents diagnosed
  and fixed in Phase I (`drain_pending` flag in `mold_strip`, sticky valid in `msg_boundary`).

## Which risks fired

Cross-referenced against §8 of the M03 design spec:

- **"Multi-message-per-packet boundary detection is the trickiest part."** Fired — see "What
  took longer" above. Mitigation (dedicated `msg_boundary.sv` with fuzz cocotb TB) caught the
  bugs but only after they surfaced in the e2e integration test, not the unit TB.
- **"250 MHz Fmax tight on a 6-stage decoder."** Did **not** fire — the design has comfortable
  margin even at 400 MHz (WNS +0.736 ns). Critical path measured ~1.76 ns regardless of clock
  constraint, so the 6-stage register boundaries did their job.
- **"Plan-text completeness gaps."** Fired three times in Phase A: `parents[3]→[4]` typo,
  `enum_name_width` calculation off-by-one, `width_col` 11→12. Each time the implementer agent
  reported BLOCKED rather than silently reconciling — saved-feedback discipline working as
  intended.
- **"`_encode_itch()` upgrade subtly changes synthetic_gen byte output."** Did **not** fire —
  M02 gates only pinned `BookEvent` SHAs, and the M03 freeze-list amendment surfaced the
  upgrade.
- **"Vivado on local-only path."** Fired in the sense that CI cannot gate timing on a per-PR
  basis. Carried to M04.

## Surprises

- `default_nettype none` rejected by Vivado for `input logic *_tready` ports (works in
  Verilator). Stripped from `type_dispatch.sv`; remaining modules already lacked it.
- Per-module `` `include `` directives collided with Vivado's glob-based file list, producing
  five "overwriting previous definition" critical warnings. Resolution: keep only the
  `book_event_pkg.sv` include (guarded with `` `ifndef ``); let the synth tool resolve module
  references from the file list.
- OOC critical path measured ~1.76 ns regardless of the constraint, indicating combinational
  depth — not optimisation headroom — sets the ceiling. 500 MHz OOC barely meets (WNS
  +0.236 ns) and would not survive PnR; 400 MHz is the conservative pick.
- SystemVerilog reserves `type` as a keyword. The `BookEvent::type` C++ field had to be
  renamed `ev_type` in the generated SV package (`_SV_FIELD_RENAMES` map in the codegen).
- `msg_boundary`'s byte-pump architecture caps steady-state input acceptance at ~0.11
  events/cycle. The plan-text floor of 0.99 was never achievable with the chosen design; we
  relaxed to 0.10 with an explicit M04 carry-over to re-architect.
- 5-way parallel agent dispatch in Phase G (per-type extractors) collapsed ~30 minutes of
  sequential work to ~5 minutes wall-time. The pattern works when each task creates one SV
  file + one cocotb TB + one Makefile shard with no shared state.

## Carried to M04

- Real-pcap validation against pinned NASDAQ TVITCH 5.0 captures.
- Byte-alignment edge cases not covered by synthetic stream.
- Self-hosted CI runner with Vivado for per-PR timing gates (decision deferred from M03).
- Throughput floor: `msg_boundary` byte-pump architecture caps steady-state at ~0.11
  events/cycle; ≥ 1 event/cycle requires either a wider field-extract path or a re-architected
  boundary stage.
- `EV_EXECPX` generator coverage gap inherited from M02 — still not addressed; M03 hand-crafts
  EXEC_PX events in the relevant TBs.
