# M02 Retrospective

## What we shipped

- `sw/refbook/` C++17 library + pybind11 wrapper.
- Frozen headers: `TobDelta`, `BookEvent`, `synthetic_gen.py` schema, refbook
  pybind11 API.
- 9 PRs (#6 – #14), 9 phases (A – I).
- 96.3 % line coverage / 100 % function coverage on `sw/refbook/src/` +
  `sw/refbook/include/`.
- 10 M-event synthetic reproducibility gate in CI.

## What took longer than planned

- **Phase F algorithmic rewrite**. The plan-prescribed C++ generator replica used
  `std::unordered_map` with `std::advance(it, rng() % live.size())`, which is
  O(N) per pick. At `n_events = 10 M` the reproducibility test was estimated to
  run for hours. After explicit user approval ("Option C") both Python and C++
  generators were rewritten to a parallel `vector + map` with swap-pop sampling,
  and both SHA pins were regenerated. C++ runtime dropped from estimated
  multi-hour to ~5 s.
- **Phase G CI debugging — four amend cycles**.
  1. `clang-16` install on ubuntu-22.04: plan called `apt-get install clang-16
     clang++-16`, but `clang++-16` is a binary name not a package, and `clang-16`
     isn't in noble's default repos. Replaced with `apt.llvm.org/llvm.sh`.
  2. `clang-16` not on `apt.llvm.org/noble`: excluded ubuntu-24.04 + clang-16
     from the matrix.
  3. lcov gcov-version mismatch on ubuntu-24.04: gcc-12 emits `B24*` `.gcda`
     while default `/usr/bin/gcov` is gcov-13 (`B33*`). Added `--gcov-tool
     gcov-N` to lcov.
  4. Detection-via-`CMAKE_C_COMPILER_*` failed silently because the project is
     declared `LANGUAGES CXX` only — `CMAKE_C_COMPILER_*` are unset. Switched to
     `CMAKE_CXX_COMPILER_VERSION`.
- **Coverage gate work**. Initial measurement at 91.9 % (below the 95 % gate).
  Added `test_book_coverage.cpp` (10 targeted tests for `Book::reset()`,
  unknown-EventType fallthrough, `on_exec_px`, `Book::snapshot()`,
  `OrderPool::at(slot) const`). Final 96.3 %.

## Which risks fired

None of the spec §9 risks fired. They are all RTL / integration-phase risks
(HBM tail, hash chain depth, URAM timing, CMAC IP licensing, U50 supply, ITCH
spec drift, CDC, M5–M7 stretch). M02 was 100 % software, so these were never
in scope.

The M02-actual risks were all plan-text completeness gaps not captured in §9:

- Plan-prescribed C++ generator was algorithmically O(N²).
- Plan-prescribed `CMakeLists.txt` omitted `install(TARGETS refbook ...)`,
  producing an empty wheel from `pip install`.
- Plan-prescribed `include(FetchContent)` was scoped inside the tests block,
  breaking bench-only configures.
- Default `OrderPool` capacity (1 M) too small for the 10 M-event reproducibility
  test and for Google Benchmark autocalibration.
- lcov 2.0 incompatible flags `--no-external` + `--include`.
- `apt.llvm.org` doesn't ship clang-16 for ubuntu-24.04 noble.
- Project's `commit-msg` hook allowlist excludes `build` and `bench` types
  used by plan-prescribed messages (substituted `chore` and `perf`).

Recommendation for M03 planning: include a "plan-text completeness check" pass
where every prescribed command is dry-run on a fresh tree before phase kickoff.

## Surprises

- Plan-text struct-format typo `<BBHIII4xQQ` (36 bytes, asserts 32) — caught and
  patched to `<BBHII4xQQ` before the first implementer was dispatched. This is
  exactly the spec-drift-via-implementer scenario the user's saved feedback
  warned about.
- `EV_EXECPX` constant is exported by `synthetic_gen.py` but never emitted by
  the generator. Both Phase F reviewers flagged it independently. Not fixed in
  M02 (FROZEN-spec interface) — deferred for M03+ tester coverage.
- `Book::decrement_shares_common` `level_empty` branch (book.cpp:198–202) is
  provably dead code: requires `rec.shares > 0` AND level `agg_size == 0` after
  decrementing by `delta ≤ rec.shares`, which is a contradiction.
- Stale-tick branches in `on_delete` and `decrement_shares_common` are
  unreachable in practice because `on_add` calls `id_map_.clear()` on rebase.
  Together with `level_empty`, ~11 lines of book.cpp are dead — candidate
  cleanup for M03 or a future spec-amendment PR.
