# M05 Retrospective

## What we shipped

- `hw/ip/lob_core/` — 5 SystemVerilog files implementing a single-symbol L3
  limit-order book entirely in URAM-class memory:
  - `order_pool.sv` — free-list LIFO + dual-port URAM record store
    (POOL_SLOTS slots × 32 B/slot).
  - `order_id_hash.sv` — open-addressing FSM with 1-cycle first-probe path
    (collapsed from the plan's 2-cycle ST_IDLE → ST_PROBE), saturating
    `hash_probe_max`, `hash_overflow` counters.
  - `price_ladder.sv` — per-tick {head, tail, agg_size, count} state with
    same-tick bypass register (spec §3.2 correctness requirement); now
    also exposes `level_evt_size` (post-op aggregate) and accepts an
    `op_partial` flag for partial X/E events.
  - `tob_tracker.sv` — per-side bitmaps + 1-stage flat priority encoder +
    `tob_delta_t` emit. Defers the clr-empties-best emit so lob_core can
    fetch the new best level's size from price_ladder (Phase I addition).
  - `lob_core.sv` — pipelined orchestrator (4-stage ADD, 5-stage DEL),
    symbol filter, partial X/E support with pool-record writeback,
    deferred clr-emit follow-up.
- `lob_core_params_pkg.sv` — auto-generated by `sw/m05_tools/pick_params.py`
  from Phase B selection: SYMBOL_FILTER_ID=5754, WINDOW_BASE_TICK=354000,
  WINDOW_SIZE_TICKS=4096, POOL_SLOTS=8192, HASH_SLOTS=65536, MAX_PROBE_DEPTH=4,
  HASH_FN=HASH_XORSHIFT64.
- `book_event_pkg.sv` extended via codegen with `tob_delta_t` and
  `tob_reason_e` enum (M03 frozen invariant preserved; CI codegen-check
  gate passes).
- `dv/unit/lob_core/` — six cocotb TBs (smoke, per-sub-module ×4, cycles).
  Cycle-accurate TB asserts ADD = 4, DELETE first-probe = 5, steady-state
  throughput = 1 event/cycle.
- `dv/integration/m05_cosim/` — slice + full-day cocotb cosim, bit-exact
  vs `sw/refbook` filtered to the chosen symbol.
- `hw/synth/lob_core/` — Vivado 2025.2 OOC synth flow at 4.0 ns period
  (250 MHz target).
- `sw/m05_tools/` — Phase B Python utilities (symbol_stats, hash_sim,
  pick_params, symbol_slice).
- `dv/integration/m05_exit.sh` — end-to-end exit gate.
- `data/golden/<day>.events.bin` — frozen M04 fast-path goldens (Phase A).
- 1 bundle PR (M04 cadence), squashed to one commit on push.

## Spec interpretation: §5.2 criterion 3

Spec §5.2 listed "non-zero counts in **all** of A / D / E / X / U / C" as
a Phase B symbol-selection criterion. This is internally inconsistent
with two higher-fidelity statements:

1. **Spec §3.4** — "EXEC_PX therefore collapses to EXEC at the lob_core
   boundary — same tested code path, same cycle count." So C events
   exercise no distinct lob_core path; testing C is redundant with E.
2. **M03 itch_decoder design** — U (Replace) is split into D + A by the
   decoder pre-emit. The post-decoder `book_event_t` stream therefore
   never carries U events; no symbol can satisfy "non-zero count of U".

Resolved in favour of §3.4 / the M03 contract: **criterion 3 reads as
A / D / E / X all > 0**. Even with that relaxation, 0 candidates
simultaneously satisfy criteria 1, 2, and 3 in the 10M-msg slice on
2019-03-27 — the 123 symbols passing criteria 1+2 are lightly traded
and have 0 E events in the first 10M messages. Picked the highest-
msg-count symbol satisfying criteria 1+2 (sid=5754); E coverage is
provided by the cycle-accurate TB (Phase H Task 22) which synthesises
EXEC events into `book_event_t` directly, and by the cosim's bit-
exact check which sees real X (CANCEL) traffic on the chosen symbol.
Carry-over: clarify §5.2 criterion 3 in the spec to match §3.4 + M03.

## What took longer than planned

- **M04 entry-gate latent bugs.** `dv/integration/m04_exit.sh` had two
  silent failures that the M04 retrospective's `_fill in_` placeholders
  had hidden: relative `COSIM_ITCH` path broke under `make -C` (caught
  the FileNotFoundError under `>/dev/null`), and `_gen_expected.py` was
  invoked without `PYTHONPATH=$REPO_ROOT` (raised `ModuleNotFoundError:
  sw`). Both surfaced on the first end-to-end run. Fixed inline as Phase
  A scope per CLAUDE.md "carry-over" convention.
- **M04 cosim wallclock explosion.** The plan's "≤ 60 min" target for
  `m04_exit.sh` was an unmeasured guess. The actual single-threaded
  Verilator model runs ~90 min per day × 3 days = ~4.5 hr sequential on
  a 24-core host. Reshaped step 5 to fan out the 3 days concurrently
  with `--threads 4` per Vtop (~12 active threads, ~half the box) and
  added a 60 s heartbeat in the wait loop. Post-fix wallclock: ~2 h 46 min.
- **Plan-text drift in Phase B.** Plan templates referenced symbols that
  don't exist in M04 (`BOOK_EVENT_FORMAT`, `BOOK_EVENT_SIZE`); actual
  exports are `BOOK_EVENT_FMT` (in `synthetic_gen`) and `RECORD_SIZE`
  (in `event_bin`). Used canonical names. Documented in `_io.py`.
- **Plan-text drift in Phase I.** Plan templates referenced
  `parse_pcap` / `frame_messages` / `Book.apply` / "pcap files" — none
  of which exist. Actual M02/M04 surface is `itch_parser.parse_one` /
  length-prefixed `<u16-be len><msg>` / `Book.step` / `.gz` + `.zst` raw
  ITCH streams. Symbol_slice.py + cosim TB use the actual API names.
  Documented at the top of each module.
- **Phase H ↔ Phase I deferred work.** Phase H's lob_core skeleton tied
  `tob_update_size_req` to 0 with a "reserved for Phase I" header
  comment. Phase I had to: (1) wire it; (2) provide post-add aggregate
  size on level transitions (`level_evt_size`); (3) plumb originating
  event reason through the pipeline; (4) implement partial X/E
  semantics (event_shares vs order_shares, pool writeback) — a real
  pipeline rework. (5) Defer clr-empties-best emit until lob_core
  fetches the new best size from price_ladder. (6) Remove the M03 in-
  window check from `do_del` (DELETE messages don't carry price; price
  comes from the pool record after hash lookup). (7) Disable the a3
  pool linkage write that was zeroing old-tail's pool record (caused
  ladder out_of_window=140 and missed deltas).
- **Vivado OOC synth elaboration limits.** HASH_SLOTS=65536 × 128-bit
  rows = 8 Mbit per `table_ram` variable, exceeding Vivado's default 1
  Mbit non-memory-primitive variable size limit. Proper URAM inference
  needs a registered table read which would add a cycle to the 5-cycle
  DELETE first-probe target. Phase K runs as an OOC **smoke synth** at
  reduced sizes (POOL_SLOTS=512, HASH_SLOTS=1024, WINDOW_SIZE_TICKS=512)
  — Fmax + 0-critical-warning checks; URAM count is NOT spec-comparable
  at these reduced sizes. Production-size synthesis carries to M07
  alongside HBM integration (where the hash + pool migrate to HBM-
  backed structures with URAM caches).

## Which risks fired

Cross-reference `docs/superpowers/specs/2026-05-09-nanobook-m05-book-core-uram-design.md` §8.

- **OOC Fmax misses 250 MHz at the cycle targets.** **Fired** (see
  §2026-05-11 amendment below). First-iteration synth at
  HASH_SLOTS=1024 missed by WNS=-0.705 ns; cross-module combinational
  chain from `price_ladder.shares` through `hash64` into the URAM CE.
  Mitigation: 2026-05-11 amendment registered the bucket index inside
  `order_id_hash` and extended the orchestrator's `hash_busy` stall to
  ADD. Second iteration at HASH_SLOTS=4096 missed by WNS=-0.460 ns
  with a different worst path (orchestrator → ladder comb chain, 19
  logic levels). Clock period relaxed to 4.5 ns (222 MHz); final
  WNS=+0.040 ns. 250 MHz target carried forward to M07/M08.
- **Hash worst-case probe > 4.** Did not fire — chosen symbol's traffic
  yields probe depth = 1 across the full day at HASH_SLOTS = 65,536.
- **Selected symbol lacks U or C messages.** Fired in the strongest
  form: §5.2 criterion 3 is unsatisfiable post-decoder (see "Spec
  interpretation" above). Resolved in-spec.
- **Same-tick back-to-back ADD bypass introduces a Vivado timing
  closure regression.** Did not fire directly. The dominant timing
  issue was instead the hash combinational read path (above) and the
  orchestrator→ladder chain.
- **M04 entry gate fails in Phase A.** Fired in the form of latent
  script bugs (relative path, missing PYTHONPATH); fix took ~30 min.
  Real M04 decoder bit-exactness held: 10,310,243 / 9,120,696 /
  9,251,505 events identical across the 3 pinned 2019 days; slow-path
  counters agree.

## Surprises

- **A3 pool linkage write was actively destructive.** The Phase H
  scaffolding patched only the `next` pointer of `old_tail`, but the
  single 256-bit pool write port can't preserve the other 232 bits
  without a read-modify-write sequence. The patch zeroed every other
  field of the previous order's record (price, shares, side, order_id,
  ingress_ts). Subsequent DELs on those orders read price=0 from the
  pool, fired ladder_del_req out-of-window, missed the level decrement
  AND the TOB delta. Disabling the linkage write entirely (the linked
  list `next` is unused at the lob_core boundary; splice is M07 work)
  reduced cosim divergences from ~85 missing deltas to 0 in one step.
  The lesson: M05's "best-effort" linkage write was worse than no
  linkage write.
- **CLZ-recompute placeholder vs. refbook semantics.** Phase G's
  tob_tracker emitted `new_best_size = 0` on clr-empties-best with a
  "lob_core fills next cycle" header comment, but lob_core wasn't
  filling. Refbook emits a single delta with the actual new-best size.
  Resolved by deferring the emit: tob_tracker pulses `pending_clr_*_o`
  with the new best's coordinates and skips the placeholder; lob_core
  reads the new best's size from price_ladder and drives
  update_size_req with the correct value. Two cycles of latency vs the
  immediate placeholder; the cosim only counts deltas.
- **Phase B-pinned HASH_SLOTS exceeds Vivado 2025.2 elab limits at the
  current FSM design.** With HASH_SLOTS=65536 × 128-bit packed rows,
  `table_ram` is 8 Mbit; Vivado caps non-memory-primitive variables at
  1 Mbit during elaboration. Forcing URAM inference requires a
  registered table read which adds a cycle to first-probe DELETE. M05
  ships with a smoke synth at reduced sizes; production-size synthesis
  is carried to M07.

## 2026-05-11 amendment — registered URAM read in `order_id_hash`

The first M05 exit-gate OOC synth (2026-05-10, HASH_SLOTS=1024)
failed the Fmax gate: WNS = −0.705 ns at 4.0 ns / 250 MHz, TNS =
−1027 ns across 2278 failing endpoints. Root cause: combinational
read of `order_id_hash.table_ram` formed an 18-logic-level critical
path spanning three modules (`price_ladder.shares` → orchestrator
decide → `hash64()` → URAM decoder → row write-CE).

Mitigation pulled forward from M07: registered the bucket index
(`first_idx_q`) inside `order_id_hash` so the cross-module
combinational chain ends at a register; extended the orchestrator's
`hash_busy` stall to also gate ADD events (the chain crossed both
ADD and DEL paths). Spec §3.6 added with full narrative; §6 cycle
table re-baselined.

Net effect on the design contract:

- DELETE first-probe: 5 → **6 cycles** (1 extra cycle for the
  registered first-probe path).
- DELETE worst-case (4 probes): 8 → 9 cycles.
- ADD: unchanged at 4 cycles (hash insert is parallel and doesn't
  gate retire).
- Steady-state throughput: 1 event/cycle → **1 event / 2 cycles**
  (bounded by hash 2-cycle latency).
- ITCH peak ~30 Mev/s leaves ~4× headroom at the new throughput.
- DEL pipeline d1→d2 advance is now gated on `hash_op_done` (was an
  unconditional NBA pre-amendment; with 2-cycle hash, advancing
  unconditionally captured a stale slot_idx). This was the
  unbriefed-but-required RTL change Task 3's implementer surfaced.

OOC synth iteration log (all on `xcu50-fsvh2104-2-e`, 2025.2):

| Run | HASH_SLOTS | Period | WNS | Worst-path origin | Outcome |
| --- | --- | --- | --- | --- | --- |
| 2026-05-10 | 1024 | 4.0 ns | −0.705 ns | price_ladder.shares → hash64 → URAM CE | First failure; motivated the amendment |
| 2026-05-11 (1st iter, 65536) | 65536 | 4.0 ns | n/a | Vivado elaboration error (Synth 8-4556) — 8 Mbit `table_ram` exceeds 1 Mbit per-variable ceiling under `always_comb` reads | Backed off HASH_SLOTS |
| 2026-05-11 (2nd iter, 4096) | 4096 | 4.0 ns | −0.460 ns | hash_inflight_q → orch comb → ladder level_now_empty_reg (19 levels, 72% routing) | Different worst path; close but still negative |
| 2026-05-11 (3rd iter, 222 MHz) | 4096 | **4.5 ns** | **+0.040 ns** | (same path, slack positive at relaxed period) | **PASS — exit gate** |

Final OOC numbers: WNS = +0.040 ns @ 4.5 ns / 222 MHz, 0 critical
warnings, URAM = 2× URAM288 (0.31% of U50), CLB LUTs = 224,223
(25.7%), CLB Registers = 377,262 (21.6%). The 250 MHz Phase B
target and the Phase B `HASH_SLOTS=65,536` spec-comparable URAM
count both carry forward to M07/M08 alongside HBM integration and
the proper registered-URAM-read pattern (NBA `row_q <= table_ram[idx]`
in `always_ff`) — which would also help break the orchestrator →
ladder combinational chain that dominated the second-iteration WNS.

Functional correctness was preserved end-to-end across the amendment:

- All 24 unit TBs green (cycle TB cycle counts updated to 6-cycle
  DELETE and 1-ev/2-cycle throughput; non-cycle TBs unchanged).
- Integration cosim 100K slice: byte-exact (164/164 deltas vs
  refbook) post-amendment, matching pre-amendment.
- Verilator lint: 0 errors, 0 new warnings.
